# M13 Branding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In an M13 run, the `run-milestone` skill walks this plan's `workflow-tasks` block instead.

**Goal:** Rebrand the site as *PNW Health Atlas*, in the Evergreen field guide direction, on one token system that every component uses. Apply the approved sensitivity decisions. Fold in #296, #277, #278, #272 and #274.

**Architecture:** The work is web-first.
- **Tokens:** `web/src/styles.css` holds every colour, type, radius, spacing, elevation and focus token, for light and dark.
- **Tests and guards:** `tokens.test.ts` checks contrast, and a new data-separation check keeps brand colours away from data colours. A new token-usage test stops raw values outside the token files, and it widens area by area as each area is swept.
- **Brand surfaces:** the mark, wordmark, favicons and social tags live in a small `web/src/brand/` module and in `index.html` and `404.html`.
- **Sensitivity decisions:** applied as web copy, plus three catalog descriptions. No export-contract change.

**Tech Stack:** React 19, Vite, Tailwind v4, Radix (`radix-ui`), Vitest, Playwright, `@fontsource-variable/figtree`; Python 3.12 pipeline (catalog only).

**Spec:** `docs/superpowers/specs/2026-11-14-m13-branding-design.md`
**Sensitivity table (approved with this plan):** Appendix A of the spec

## Global Constraints

- **Name and tagline (verbatim):** "PNW Health Atlas" and "County health across Washington, Oregon, Idaho and Alaska."
- **Page titles:** `PNW Health Atlas`, `Methodology · PNW Health Atlas`, `About · PNW Health Atlas`.
- **Brand starting values (light):** fir `#14302a`, evergreen `#2b6b55`, mint `#8fcfb3`, paper `#f2f5f1`, sun `#f2c46d`. They may be adjusted to pass the tests, but must stay in the same hue family.
- **The sun colour is mark-only.** It never appears as an interface token or in charts.
- **Data colours never move:** `schemeOrRd[5]`, `schemeBlues[5]`, the tier fills (`#ca0020`, `#f4a582`, `#92c5de`, `#0571b0`), `tierNone`, and the hatch.
- **Token mapping:**
  - `--fir` is the header and brand surface.
  - New `--evergreen` takes every current accent use of `--fir`.
  - `--fir-soft` becomes the mint tint.
  - `@theme inline` stays the Tailwind bridge.
- **Font:** Figtree Variable, from `@fontsource-variable/figtree`. Archivo is removed. Figures keep `tabular-nums` where numbers align.
- **The repo name and Pages base stay** `/pnw-health-dashboard/`.
- **Social origin:** `VITE_SITE_ORIGIN`, defaulting to `https://edward-sf.github.io`.
- **Contrast (WCAG AA):** text 4.5:1, large text and UI parts 3:1, focus 3:1 against every surface it sits on, in both themes.
- **No export-contract or `schema/` change.** Category value `Behaviors` and flag names are unchanged.
- **Copy:** the model's factors are *associated with* its estimate, never causes (AGENTS.md). Sensitivity wording is exactly as in the decision table.
- **E2E:** specs import `test` and `expect` from `./fixtures`. They wait on observable conditions, never fixed sleeps.
- **Run e2e from a production build:** `cd web && npm run build && CI=1 npx playwright test`.

2. **The header at 320px wide**, with the wordmark, tagline and theme button. Expected:
   - nothing overlaps or clips;
   - the page doesn't scroll horizontally;
   - the tagline may hide, but the wordmark and nav stay.

   Test in Task 5.
3. **Social tags under the Pages base path.** Expected: `og:image`, `og:url` and `twitter:image` are absolute and include `/pnw-health-dashboard/`, and the file each points to exists in `dist/`. Test in Task 5.
4. **Switching between outcomes with opposite directions**, from Life expectancy to Premature death and back. Expected: the tier labels in the legend, panel, table and tooltip flip between "higher" and "lower" to match each outcome, with no stale label. Test in Task 7.
5. **A legend with fewer than five bins**, where few distinct values give two or three colours. Expected: it is still one ordered scale, with the end labels on the first and last bins. Test in Task 6.

### Task 1: Fix the pages404 locked-directory flake

`e2e/pages404.spec.ts:79` creates a fixed `dist/locked-for-e2e/` directory. Under `--repeat-each`, parallel workers share that path, so one worker's `finally` can remove or unlock the directory while another worker is requesting it. That worker then gets a 404 or a 200 instead of a 500. Fix it by giving each run its own directory.
