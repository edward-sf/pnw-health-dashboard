# PNW Health Dashboard — Roadmap

**Spec:** `docs/superpowers/specs/2026-11-10-pnw-health-dashboard-design.md`
**Workflow:** `CONTRIBUTING.md`

Each milestone below is a GitHub Milestone, and each `M<N>.T<k>` line is one GitHub Issue. Issues for M2 onward are **provisional**: when a milestone starts, its detailed plan is written and its issues are reconciled to match (see CONTRIBUTING, "Plans are just-in-time").

## M0 — Project setup (no plan file; done by hand)

- Create the public GitHub repo, push `main`, enable GitHub Pages (source: Actions).
- Create labels, milestones M1–M6, and the Project board with its Status field.
- Create issues from this roadmap. M1 issues go to `Ready`; others stay in `Backlog`.
- Start M1 according to CONTRIBUTING's milestone lifecycle: create `milestone/m1` from `main` and open the draft milestone PR.
- Install the local toolchain: `uv` (present) with Python 3.12 via `uv python install 3.12`, and Node 26 LTS (needed from M2; pin it in `web/.nvmrc` and the CI setup-node step).

## M1 — Pipeline foundation
**Goal:** `pnw-health run` fetches ACS and county boundaries, harmonizes, validates, and exports `manifest.json`, `values.json`, and `counties.topojson`. JSON Schema files are generated from the contract and committed in `schema/`.
**Exit:** a live run produces files that validate against the contract; all pipeline tests pass offline.
**Plan:** `2026-11-10-m1-pipeline-foundation.md`

- M1.T1 Scaffold pipeline package and shared config
- M1.T2 Indicator catalog (ACS subset)
- M1.T3 Fetch and cache layer (atomic writes, HTTP errors)
- M1.T4 ACS source
- M1.T5 Harmonize: FIPS and Alaska geography changes
- M1.T6 County boundaries → TopoJSON
- M1.T7 Validation checks
- M1.T8 Contract, ranks, and export
- M1.T9 CLI and end-to-end run

## M2 — Map + live site
**Goal:** a React site shows a choropleth of any M1 indicator for all 149 counties and is deployed to GitHub Pages by CI.
**Exit:** public URL live; `ci` required on PRs; `build-deploy` proven on the milestone branch before merge and by a manual run on `main` after merge; monthly cron configured.

- M2.T1 Scaffold Vite + React + TS app with lint, typecheck, Vitest, and type generation from JSON Schema
- M2.T2 `useData()` hook and error state
- M2.T3 Composite projection (Albers PNW + Alaska inset) and SVG county map
- M2.T4 Color scales (direction-aware, neutral, quantile bins, hatch for null) and legend
- M2.T5 Indicator picker and URL state (`i`, `c`, `mode`, `view`) with bad-param fallback
- M2.T6 Routing (`/`, `/methodology`, `/about` stubs) and Pages `404.html` fallback
- M2.T7 `ci.yml` (pipeline + web checks on PRs into `main` and `milestone/**`) and branch protection on `main`
- M2.T8 `build-deploy.yml` (pipeline with raw cache → build → Playwright smoke → Pages; monthly cron)

**Exit:** about 30–40 catalog indicators live; the panel shows value, CI, ranks, strip plot, legacy notes, and "Who lives here."

- M3.T1 PLACES source + catalog entries
- M3.T2 CHR source + catalog entries (incl. life expectancy with CI)
- M3.T3 CHR 2023 fallback for Valdez-Cordova

## M4 — ML pipeline
**Goal:** `model.json` with ridge, LightGBM, behaviors-comparison metrics, tiered flags, and SHAP.
**Exit:** the author reviews the M4 milestone PR, including the checkpoint review, and merges it. M5 starts only after that merge.

- M4.T1 National feature/target table and fold-safe imputation
- M4.T2 State-grouped CV with OOF predictions; ridge + LightGBM metrics
- M4.T3 Tiered flag thresholds (spec §5 formula)
- M4.T4 Fold-model SHAP top-5 contributions and global importance
- M4.T5 Behaviors-comparison model (metrics only)
- M4.T6 `model.json` contract + export + model card data
- M4.T7 **Checkpoint:** review metrics, flag distribution, and SHAP samples (`checkpoint`)
