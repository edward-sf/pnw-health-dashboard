# M5 Model UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each task is one GitHub Issue (`M5.T<k>`) and one issue PR into `milestone/m5`. The milestone ends with a single milestone PR `milestone/m5 → main` for the author to review. Follow `CONTRIBUTING.md` for branch, PR, and merge rules. A task's final "Commit" step is followed by its issue PR.

**Goal:** The Explorer gains a model mode (map, legend, tooltip and table by flag tier) and every county panel gains a life-expectancy model card.

**Architecture:** `loadData` adds `model.json` to `AppData`. One pure module, `src/model/modelView.ts`, owns the tiers (order, labels, colours, sort rank, missing-county fallback); the map, legend, table and card all read from it. Pure functions own the remaining logic (`tierCounts`, `sortModelRows`, `buildShapBars`, `rangeDomain`), and thin React components render their results. All state stays in the URL.

**Tech Stack:** React 19, TypeScript 6.0, React Router 8, `@observablehq/plot` 0.6.19, d3-scale; Vitest 5, Testing Library, Playwright. No pipeline changes.

**Spec:** `docs/superpowers/specs/2026-11-11-m5-model-ui-design.md`, with parent `docs/superpowers/specs/2026-11-10-pnw-health-dashboard-design.md` and the `model.json` contract in `docs/superpowers/specs/2026-11-10-m4-ml-pipeline-design.md` §5. **Roadmap:** `docs/superpowers/plans/2026-11-10-roadmap.md`.

## Global Constraints

- All M2 and M3 constraints still apply: FIPS are 5-character strings, TypeScript stays `~6.0.3`, import from `react-router`, every URL goes through `import.meta.env.BASE_URL`, null is not zero (`??`, never `||`, on values).
- No pipeline, contract or schema changes. Types come from `src/types/generated/model.ts`; re-export `ModelFile`, `CountyModel`, `Flag` and `ShapEntry` from `src/types/index.ts`.
- Tier colours, exactly: `notably_worse #ca0020`, `somewhat_worse #f4a582`, `none #e3e3e3`, `somewhat_better #92c5de`, `notably_better #0571b0`; `insufficient_data` uses the existing `HATCH_FILL`.
- Tier labels, exactly: "Notably worse than expected", "Somewhat worse than expected", "About as expected", "Somewhat better than expected", "Notably better than expected", "Not enough data".
- The factors section uses one neutral hue (`#6b7280`) and never a tier colour.
- Copy never uses "driver(s)", "cause(s)/caused" or "because of" about the factors, and never links the factors to the difference. Spec §5 fixes the card, legend and picker-note copy; use it verbatim.
- Signed numbers use `+` and `−` (U+2212). A value that rounds to zero has no sign.
- Web checks: `cd web && npm run lint && npm run typecheck && npm test`. Playwright: `cd web && npm run build && npm run test:e2e`.

## Review Focus

1. **Mode switch with a county selected in table view.** `?c=53033&view=table` → Model keeps `c` and `view`, shows the model columns, and Back returns to the values table with the county still selected. *(Test in T3.)*
2. **A SHAP feature missing from the manifest.** The bar still renders, labelled with the raw feature id and the number unformatted, instead of crashing or showing "undefined". *(Test in T2.)*
3. **A residual beyond the 90% band.** The real data has +11.8 years against a ±3.4 band; the range graphic's domain must include the dot. *(Test in T2.)*
4. **Rounding at zero.** A residual of −0.04 shows "0.0 years", not "−0.0 years" or "+0.0 years". *(Test in T2.)*
5. **Bad and mixed-case `mode` values.** `?mode=Model` and `?mode=` are cleared to values mode without dropping `i` or `c`. *(Test in T1.)*
