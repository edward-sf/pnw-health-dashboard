## 6. Findings that escaped a layer

No red `build-deploy` escaped the gates. All eight must-fix final-review findings passed their task reviews and gates:

| Finding | Layer that should have caught it | Why it did not |
|---|---|---|
| C1 (grid blow-out, no R² bars, sideways scroll on phones) | T3 gates (e2e) and T3 review | Tests were jsdom unit tests and DOM-presence e2e. Nothing asserted a rendered width or `scrollWidth`. The reviewer reads diffs, not the rendered page |
| C2 (rail loses its place after a jump) | T5 and T7 e2e | The e2e used a `readDownTo` helper that scrolls by hand, which hid the bug. It asserted only the pinned state, never the settled one |
| I1 (smooth scroll never happens) | T5 e2e | No test sampled scroll progress. `focus()` right after `scrollIntoView` was not flagged |
| I2 (phone bar under a static header) | T5 review | Reviewed as CSS. The reviewer's M2 on `scroll-margin-top` was close but did not check what the bar sticks under (the header is `position: static`) |
| M1 (pipeline strip bullets) | T4 review | Specificity clash that only shows in computed style. The as-built note said a follow-up was logged and none existed |
| M4 (tests too narrow) | T5 and T7 reviews | Same cause as C2. T1's M3 had already flagged the `model-importance` tabindex exemption, and it stayed deferred |
| M6 (docs say things that are not so) | T7 review | Reviewers do not check doc claims against the code or the issue list |
| M8 (nested evidence boxes) | T3 review | Visual only. No screenshot check in a task review |

Four deferred findings (M2, M3, M5, M7) are copy and ARIA polish. T5's M3 had flagged the dangling `aria-controls` at task review too.

## 7. Guard proposals

Ranked by what each would have saved. The fix cycle (triage, batched-fix and delta-review) cost 12 points. The final review's 12 points are not counted as savings, because its job is to find things.

1. **Test (C1, and the layout side of I2).** New `web/e2e/layout.spec.ts`: for `/`, `/methodology`, `/about` and the county page, at 375, 721, 1100 and 1440px, assert `document.documentElement.scrollWidth <= clientWidth` and that every `[data-testid]` evidence or bar track has width > 0. It is one spec with four viewports, and it runs under the existing throttle. #357 added Methodology-only geometry tests. This generalizes them so the next layout milestone gets them free.
2. **Checklist line (C2, I1, M4).** In `workflow/prompts/task-review.md`: "For any scroll, focus or scrollspy behaviour, reject an e2e that reaches the state through a helper that scrolls or focuses for the user. Require an assertion on the settled state after a real click or key press, and one on scroll progress for smooth scroll."
3. **Checklist line (I2).** In `workflow/prompts/task-review.md`: "For every `position: sticky` or `fixed` rule, name its containing scroll parent and what it sticks under, and confirm it in the running page, not just the CSS."
4. **Checklist line (T3's extra round).** In `workflow/prompts/implement.md`: "A test of 'top N by X' or 'the selected Y' must use a fixture where the wrong implementation (unsorted, default target) gives a different answer." T3's second round cost about 175k tokens and 5 points. Each of I1 and I2 would have been a failing test case on the first pass.
5. **Checklist line (M6, and the M1 phantom follow-up).** In `workflow/prompts/implement.md`, under as-built notes: "Every 'follow-up logged' claim cites an issue number. Every claim about behaviour is backed by a test or a command you ran." It is one line and would have prevented M6 and half of M1.

No guard for M8, M2, M3, M5 or M7. They are one-selector or copy fixes that the final review already catches, and a guard would cost more than the finding. M1's other half (specificity) is covered by guard 1 only if the page layout check also reads computed styles. I did not add that, because it would cost more than the single selector it prevents.

Repeated minor, not a guard: formatter-only reflow showed up in T1 (M1), T2 (M3) and T3 (M1, in about ten files). That is a reviewer note, not a loop cost, so no guard is proposed.
